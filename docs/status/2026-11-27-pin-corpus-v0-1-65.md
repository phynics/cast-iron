# Corpus pinned to v0.1.65, 2026-11-27

`sources/corpus.toml` now pins `phynics/cast-iron-data` tag `v0.1.65`, commit
`1d78219f05a18259c44aa8c417f1ce99cc425aee` (tag object `adce0cc9e592103ae978ea83cc5884530630f836`). The tree
hash is `a7570e49b32b02ce56e336db29ea1d2ad29f8b1f46819ebcc16753e356310dba` (computed with
`cargo xtask corpus-tree-hash` on the extracted codeload archive; `cargo xtask fetch-sources` verified it).

**The seven Advanced Player's Guide base classes carry `features`** ([#540](https://github.com/phynics/cast-iron/issues/540)).
This is the first pin in which a `kind = "class"` entry lists its class features. The pin also converts 140
Ultimate Combat class options and rewrites 15 `ref/ability/*` rule entries as printed prose.

Between v0.1.64 and v0.1.65, 165 entry files changed (all modified). None was added, deleted or moved, and no id
changed; no alias, exclusion or exception changed. Outside `entries/`, only `scripts/` and the data CI workflow
changed. The library still has 31,766 entries and 445 books. The data CI on the tag commit was green (run
46040283648). Data PRs in the range:

- **Base classes:** phynics/cast-iron-data#373 writes the Alchemist, Antipaladin, Cavalier, Inquisitor, Oracle,
  Summoner and Witch as printed prose with `features`. Every anchor that a trade or a link uses is kept,
  including `extracts`, `patron-spells`, `channel-negative-energy`, `mount`, `domain` and `eidolon`. Unreferenced
  anchors are gone: the Antipaladin's `channel-energy`, `weapon-bond` and `fiendish-servant`, and the Cavalier's
  `original-standard`, `original-standard-2` and four `*-standard-2` anchors. New sections include the Witch's
  familiar sections, the Antipaladin's `code-of-conduct` and `associates`, the Cavalier's `flying-the-flag-of-war`
  and two mount sections, and `class-features` on all seven.
- **Witch familiars:** #380 adds `witch-familiar-rules` and `new-familiars` to the Witch.
- **Class options, Ultimate Combat:** #375 converts 140 single-power options.
- **Ability lists:** #379 writes 13 `ref/ability/*` lists and `ref/ability/companion-tricks` as printed prose with
  no `features` (decision `2026-11-27-rule-entries-without-features`). `ref/ability/annointings` is now titled
  "Anointings" (id unchanged), and the seven classes gain print's "The following are the class features of …"
  opening. #378 adds page rows to seven ability lists.
- **Ledgers and fixes:** #386 writes Dilution and Fast Bombs and gives Confusion Bomb its printed asterisk
  sentence. #382 and #383 change scripts only.

The 143 converted class options are in these groups: `ref/arcana/` 19, `ref/deed/` 17, `ref/discovery/` 9,
`ref/ninjatrick/` 43, `ref/ragepower/` 31 (Auspicious Mark included) and `ref/talent/` 24.

## What this pin changes in `main`

- **Specs:** none of the class and class-option specs names a changed entry as a literal that the data makes
  untrue, with one exception, found by running them: `class-options.spec.ts` (the Wizard's Also available
  capstones) failed in Chromium, because the shared Alternate Capstones entry now prints each capstone as a
  run-in head (`**Arch-Familiar (Su):** At 20th level, …`) and the app read capstone names only from the
  import form (`**Name (Ex)**` as a paragraph of its own). The names stopped linking.
- **App fix:** `also_available::names_in` also reads a paragraph that opens with a bold, tagged run-in head
  (`**Name (Ex):**`). An untagged head (`**Special:**`) is never a name. A native test covers it. WASM grows
  from 2,694,078 to 2,694,489 bytes.
- **New test:** `feature-heads.spec.ts` covers a base class. On the Inquisitor, every feature listed in the
  compiled entry is a head, Monster Lore shows `Level 1`, a feature without a level shows none, the address
  `?a=monster-lore` scrolls to the head, and a search for "Monster Lore" finds the Inquisitor with the feature
  as its anchor. A class page has the section switcher in place of `On this page`, so the test checks the
  switcher and the deep link, not a contents list.
