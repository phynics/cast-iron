# Corpus pinned to v0.1.66, 2026-11-27

`sources/corpus.toml` now pins `phynics/cast-iron-data` tag `v0.1.66`, commit
`4d635089edcd34ad0c6d5a1e30b61d1e5fe728f1` (tag object `dc73003eb8c94178ae67460c0e7c7440679c184f`). The tree
hash is `9764fb40f9fb2c76ad6468cddde9c20a409ba5a9fb015892b28b1c4318bab76f` (computed with
`cargo xtask corpus-tree-hash` on the extracted codeload archive; `cargo xtask fetch-sources` verified it).

**Ten Core Rulebook base classes carry `features`** ([#540](https://github.com/phynics/cast-iron/issues/540)).
The Barbarian, Bard, Cleric, Druid, Fighter, Paladin, Ranger, Rogue, Sorcerer and Wizard are printed prose with
`features`, as the seven Advanced Player's Guide classes were in v0.1.65. The Monk is held back. The pin also
converts 257 class options of the Advanced Class Guide, the Core Rulebook and Ultimate Intrigue.

Between v0.1.65 and v0.1.66, 287 entry files changed (all modified). None was added, deleted or moved, and no id
changed; no alias, exclusion or exception changed. Outside `entries/`, only `scripts/` changed. The library still
has 31,766 entries and 445 books. The data CI on the tag commit was green (run 46058247019). Data PRs in the range:

- **Base classes:** phynics/cast-iron-data#389 writes the ten classes as printed prose with `features`, and their
  `ref/rule/class-<c>/<c>` copies. It adds print's lead-in sections to the Advanced Player's Guide Alchemist,
  Cavalier, Inquisitor and Witch, rewrites their Ex- sections from print, adds the Oracle's asterisk sentence to
  `ref/ability/mysteries`, and retargets three Paladin archetype trades (Silver Champion, Tortured Crusader,
  Vindictive Bastard) to `channel-positive-energy`. `class-features` is a new key on each class.
- **Removed heading keys,** none of them used by a trade or a link: the Druid's `domain`, `companion` and the old
  `herbalism` (the key now names the "Druidic Herbalism" section), the Wizard's `familiar` and `bonded-object`, the
  Ranger's `companions-bond` and `animal-companion`, and the Paladin's `channel-energy`, `bonded-weapon` and
  `bonded-mount`. New keys include the Paladin's `code-of-conduct` and `associates` and the Cleric's `domain-list`.
- **Class options:** #377 converts 126 Advanced Class Guide options, #388 and #391 convert 69 Core Rulebook options,
  and #385 converts 68 Ultimate Intrigue options.

The 257 converted class options are in `ref/arcana/`, `ref/discovery/`, `ref/exploit/`, `ref/invtalent/`,
`ref/performance/`, `ref/ragepower/`, `ref/shamanhex/`, `ref/slayertalent/`, `ref/soctalent/`, `ref/swashdeed/`,
`ref/talent/` and `ref/vigtalent/`.

## What this pin changes in `main`

- **Specs:** none of the specs names a changed entry, heading key or class-card value as a literal that the data
  makes untrue. The class-card values, the archetype lists, the Alternate Capstones text and the archetype trades
  of the ten classes are unchanged in the data. The class specs read their expectations from the compiled corpus.
  No app change was needed.
- **New test:** `feature-heads.spec.ts` covers a Core Rulebook base class as well as the Inquisitor. On the Fighter,
  every feature listed in the compiled entry is a head, Weapon Mastery shows `Gained at Level 20`, the address
  `?a=weapon-mastery` scrolls to the head, and a search for "Weapon Mastery" finds the Fighter with the feature as
  its anchor. Both tests share one function.
- **Two data observations for the data thread.** The Barbarian, Fighter, Rogue and Cavalier print two top-level `Class
  Features` headings: the level table's, which has no anchor, and the section's, which has `{#class-features}`. The page derives
  `class-features` for the first and `class-features-2` for the second, and the Features stop and the Options rows
  use the first, so they work. The Wizard no longer prints the Advanced Player's Guide paragraph
  `**Arcane Discoveries:**`, so the Options row of the Arcane discoveries group has no feature to sit under; the
  chip and the list in the Options section still work, and no spec depends on the row.
