# Spell hub, class lists and the school multi-select, 2026-11-15

Refs [#193](https://github.com/phynics/cast-iron/issues/193), PR 5 of 5. The council left this slice last: "the spell-list multi-select (waits for #182)". #182 (density) is built, so the slice lands now.

- **What multi-select means for spells: several schools on one class list.** The council's note names the school filter of a spell list, a `<details>` of checkbox pills today, to become a checkbox panel with the trigger `School: 2 chosen`. It is that, not "class and level together". A school is one value of one field, so several schools are a plain OR, and the search engine already matches several values of one facet that way (`crates/search`, "OR within a facet field"). Class and level are not combinable as search facets: the index holds `class` and `spell_level` as two independent facets per spell, so `class:wizard` with `spell_level:3` also matches a spell that is level 3 for a Cleric and level 5 for a Wizard. A class list is already the exact pair (`lists.json`), and it stays the way to see "Wizard level 3". A combined facet would need a compiler and index change plus a library update, so it is left out; the kind page does not offer Class or Level menus, for the same reason.
- **The route is the state, and a tick is one history entry.** `#/spells/Wizard/3?school=evocation&school=conjuration` (`Route::SpellList.schools`: lower case, in the order chosen, each once). Back undoes the last tick and Forward replays it. A level link keeps the schools, so "Evocation or Conjuration" can be read level by level. A school that is chosen but has no spell on the level stays in the panel with a count of 0, so it can be cleared.
- **The page is not rebuilt for a tick.** The app's page memo drops the schools from the key (like Search and a book's chapter), the list reads them from the route signal, and the route frame leaves scroll and focus alone (`spells::same_spell_list`). The panel therefore stays open, the checkbox keeps focus, and a reader can tick three schools in a row. `route::push` pushes the entry and updates the route signal in the same turn; a plain hash change reaches the signal one event later, which a checkbox that shows the route's state would miss.
- **One menu component.** `FilterMenuButton` and `MenuState` are the single-choice menu's own; `MultiFilterMenuPanel` is the same panel with checkbox rows (`<label>` of 44 px, native `<input type=checkbox>`, count at the right). The rows are not links: a checkbox is the honest control for a set, and the toggle row of DESIGN.md already makes the whole `<label>` the target. `All schools` stays a link. There is no find field: the menu has nine schools, below the threshold of ten.
- **The class list's head follows the template.** Crumb (`Spells › Spell lists`), `h1`, count line (`45 of 199 spells · Show all`, `26 cantrips` at level 0), filter row (`School` and the `Class page` `.page-link`, which replaces the bordered `.jump` rectangle), then the name field, the level bar, the density choice and the rows. `Show all` clears the schools and the name field. The count line is the one status; the old `N spells` line above the rows is gone.
- **Deviation from the council: the level bar is not sticky.** The council let a spell list's level bar take the letter bar's slot. The bar holds `All levels` and up to ten level targets of 44 px or more, which wrap to two rows at 390 px (about 110 px); sticky would take an eighth of the viewport. It stays in the flow below the name field.
- **The hub is the head and the picker.** `h1`, a count line (`31 spell lists`), then the class picker. The `By school` pill wall (it linked into search) and the `All spells, A to Z` link are gone: the school menu lives on the Spells page (one tap from the crumb) and on each list.
- **Scope for Quick search.** The hub scopes to `Search spells`. A class list scopes to the class and the chosen schools: `Search Wizard spells`, `Search Evocation or Conjuration Wizard spells`. Values of one field read joined by "or", and a class comes last, next to the noun. The level is not in the scope, for the reason above; the brief's example `Search Wizard 3rd spells` would show spells that are not on the Wizard's level 3 list, and a scope that names more than it searches is worse than one that names less. The scope is applied exactly (`class` and `school` facets), and the results page and recent searches already carry it.
- **Not changed.** The Spells kind page keeps its single-choice `School` menu (a spell has one school, so it narrows the A to Z list the same way, and the council kept it one choice). The name filter and the density choice stay on the list page. No schema, search format or corpus change.

### Review round 2 (PR 392), 2026-11-15

- **A level heading keeps the schools.** In the whole-list view the `Level 3` heading links to `#/spells/Wizard/3?school=…`, like the level bar. Both now build the route from the chosen schools.
- **`All schools` is the current choice while nothing is chosen, so it only closes the panel** (no navigation, no history entry, focus to the button). With schools chosen it clears them and the panel stays open. It shows a drawn box ticked while current, so the first row reads like the others; it stays a link because it resets rather than toggles.
- **The scope pill wraps instead of being cut.** `.scope-pill` text wraps (the cross stays at the right, the pill stays at least 44 px), here and on the results page and for the book filter pill. The field's placeholder (`Search Evocation or Conj`) still ends in a cut: an `<input>` placeholder cannot wrap, and the pill under it carries the whole scope.
- **`route::push` starts the new entry with no history state, on purpose.** `scrollId` belongs to one entry (a copy would give two entries one scroll offset) and `quickSearch` marks the entry Quick search pushed (a copy would mark every tick as one). `push_flagged_entry` copies because it flags the page that is on screen. The doc comment says so.
- **All spells A to Z is reached from the `Spells` crumb** on the hub and on a class list (`#/browse/kind/spell`, with the single-choice School menu), and from the Spells card on Home. The hub test follows the crumb.
