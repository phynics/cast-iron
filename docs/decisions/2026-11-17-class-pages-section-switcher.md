# Class pages: section switcher, 2026-11-17

Refs [#170](https://github.com/phynics/cast-iron/issues/170), part A. Parts B and F landed in #433 and part C in #391; the archetype list (D) and the class options section (E) are other parts. A class page is one long document (Wizard is about 29,000 px at 390 px), and the `On this page` disclosure listed every heading, 40 or more of them.

- **Anchored sections with a sticky jump bar, not ARIA tabs.** The issue allowed either. The page stays one document and the bar only moves it, so every section is in the DOM and visible: Find in page (Ctrl+F) matches text in all of them, a screen reader's heading list and landmark list reach all of them, and the existing `?a=<heading>` deep links, the `Referenced by` links into a class and a printed page all keep working. A tab panel that shows one section would hide the others with `hidden` or `display: none`, which removes them from Find in page and from the accessibility tree, and it would break every link to a heading inside a hidden panel until a script opens the panel first. It would also need roving focus and arrow keys (a `tablist` that does not respond to them is wrong), and a way to keep the unchosen panels' text, about 10,000 px of archetypes, from rendering twice or never. The cost of anchors is that "each section shows only its content" of the issue's proposal is not met: the reader scrolls past other sections. The jump, the pinned bar and the page's length being the reader's to scan are the answer to that, and the archetype list (D) will shorten the longest section.
- **The stops are headings the corpus already types.** `class_sections.rs` reads them; no entry, anchor, id or stored file changes, so `SCHEMA_VERSION` and the compiler output stay as they are (rule 3, rule 5).

  | Stop | Starts at | Classes that have it |
  |---|---|---|
  | Overview | the top: title, summary card, introduction | all |
  | Features | the first heading of the shallowest level whose title begins `Class Features` (`Class Features`, `Class Features and Spells Per Day`) | all 49 classes and all 115 prestige classes |
  | Archetypes | the heading of that level titled `Archetypes` | the 44 non-NPC classes; not `Archetypes by Feature`, not an archetype's own deeper `Class Features` |
  | Spells | the `Spell list` panel (`h2#rel-spells`), which exists when `lists.json` has the class | the classes with a spell list |

  The Spells stop is the panel, not the body's `Spells` feature, because the panel is where a reader goes next (the level links and the list) and it is the last of the three stops in the page, so the stops are in document order. The body's `Spells` heading stays reachable by its own `?a=spells`. Each body heading carries `data-class-section` and `tabindex="-1"` (set in the renderer from the shared heading keys, so they cannot drift from `keyed_headings`), and the panel's `h2` carries the same attribute.
- **At least three stops, or the page keeps what it has.** A bar of two (a prestige class has only Overview and Features, as do four of the five NPC classes; Adept also has Spells) adds a jump the short page hardly needs, so those pages get no switcher and keep their contents disclosure, which shows only from four headings (Arcane Archer has three, so it has none). A prestige class's missing route to Requirements is #443, a separate follow-up that this part does not close. Wizard, Arcanist and the other casters get four stops; the classes with archetypes and no spell list (Fighter) get three.
- **`?s=` is a query, not an id.** `Route::Entry` gets `section: Option<Section>`; `#/entry/ref/class/wizard?s=archetypes`. The entry id is untouched (rule 3), `a=` and `book=` keep their meaning and `a=` wins over `s=` when both are present. Overview has no value (the plain address), and `s=overview`, an unknown value and an empty one parse as no section. A stop that the class lacks (`?s=spells` on Fighter) opens at the top. The section is its own field and not an anchor because the heading keys of a class are not stable names (five of the 49 classes had no explicit anchors before #252, and a key is suffixed when a title repeats), while `archetypes` is the name of the stop.
- **A stop is a history entry; Back is the browser's.** A stop is a plain link, so the browser pushes an entry and the app's scroll memory handles Back as it does for any entry. Back from `?s=spells` goes to `?s=archetypes` and the Archetypes heading; Back from the first stop goes to the plain address and the offset where the reader left it. The jump is by route, so a reload and a shared link open at the same place.
- **A jump does not rebuild the page and does not move focus to `<main>`.** `RouteView`'s memo drops `section` from the route it keys on (as it does for a spell list's schools), so open disclosures and the reader's place are kept, and `Reader` treats a change of section alone as no reason to focus `<main>` (`Route::only_section_differs`). The jump puts focus on the section's heading (`preventScroll`, because the jump has scrolled), so the next Tab enters the section and a screen reader reads its name. On a first load the page jumps itself after it renders, like `?a=`. A stop chosen from an `?a=` address is the same jump: `Route::is_section_jump` is true when the next address is the same entry and book with no anchor, and the memo keeps the shown anchor in its key, so the click clears `a`, scrolls, focuses the heading and rebuilds nothing. A move to an `?a=` address stays an ordinary navigation. Both frames that move focus (`Reader` for a jump, `EntryView` on a first load) have the race that #419 describes (no cancel by a newer navigation, no yield to a control the reader focused); they are marked in the code and go with that issue.
- **A section the page lacks is dropped from the address.** `?s=spells` on a fighter, any `?s=` on a prestige class and on an entry that is no class open at the top, and the address is replaced (no history entry) by the same address without `s=`, so the address and the page agree. An `?a=` in the same address stays. The drop follows the route, so an address with such a section typed into the page on screen is replaced too, not only one the page was opened with. A retired id keeps its `?s=` through the redirect to the canonical id.
- **The current stop is the last one chosen, not a scroll-spy.** `aria-current="true"` follows the address. Following the scroll position needs an observer or a scroll listener that reads layout, flickers at a short section, and cannot mark Spells when the page ends before the heading reaches the top. The cost is that the mark can be stale after the reader scrolls by hand; the address and the mark agree with each other, and the bar's job is to jump. Recorded as a possible follow-up if reviewers find the stale mark confusing.
- **Look: Navigation role, no tabs, no pills.** Rectangles of the card radius, 44 px tall, with `flex: 1 1 auto` so a long label gets room; the current stop is filled with `--accent`, the same wayfinding as the spell level links. Sticky at `top: var(--header-h)`, `z-index: 4` under the masthead, on an opaque `--bg` that runs to the page gutters with a short fade under it. `scroll-margin-top` puts a section's heading below the bar.
- **Wide screens: one block column.** The wide entry is a CSS grid, and a sticky grid item cannot leave its grid row, so a class page that has the switcher is `display: block` from 64 rem. Its order is the document's, which is also the order the folded class page already used (#433). A class page with a switcher has no side panel there, as before.
- **`On this page` is gone from these pages.** The 40-odd feature headings are no longer listed in one disclosure on Wizard; a feature stays reachable by its `?a=` address, from the summary card, from search, and by scrolling the Features section. This is what the issue asks (the switcher replaces it); the lost route to one feature is what a reader may miss, and the answer would be an in-section index in a later part, not a second contents list here.
- **Checked** (light and dark, 390 and 1280 px): Wizard, Fighter, Arcanist, Arcane Archer (prestige, no switcher), Adept (NPC with Spells). `class-sections.spec.ts` covers the stops, the first viewport at 390 px, a jump and its address, the pinned bar, deep links, Back and Forward, and the keyboard. Native tests cover the mapping and the route.
