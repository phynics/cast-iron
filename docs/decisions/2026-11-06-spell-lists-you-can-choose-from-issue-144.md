# 2026-11-06: spell lists you can choose from (issue #144)

- **Owner decision: two-line spell rows, three lines on a phone.** A row on `#/spells/<Class>/<level>` shows the name and the school (a muted Label, not a pill) over a muted fact line: casting time · saving throw · gist · book. A missing fact is left out. Rows are at least 44 px with a hairline separator, and the name truncates instead of wrapping. `#/spells` opens with a class picker of `.jump` rectangles, with Wizard, Sorcerer, Cleric, Druid, Bard, Ranger and Paladin first and every other list after them. The 30 stacked class cards and their level chips are gone from the hub; the level navigation stays on the class page.
- **The rows get their data from `lists.json`, not from the entries.** The list needs school, casting time, save and gist for thousands of spells, and the client must not open every spell shard to draw it. `SpellLists::details` is a vector parallel to `spells` (entry `i` belongs to `spells[i]`; the field docs state this and `validate_derived` enforces the length): `{school, casting_time, saving_throw, gist}`, each field omitted when empty. The book comes from the catalog stub that the client already holds. `validate_derived` fails when `details` is neither empty nor as long as `spells`. `lists.json` grew from 267 KB to about 800 KB uncompressed, and it loads only on the spell screens.
- **Schema stays 3 and the search format stays 1.** The field is additive and serde-defaulted. An older library has no `details`, so its rows show the title alone and no school filter appears; an older client ignores the field. This follows the precedent of `backlinks.json` (AGENTS.md rule 4 asks for a bump only on a breaking change).
- **The gist is the first sentence of the description, cut at a word to 70 characters.** The corpus has no short description. The first sentence is deterministic and needs no reviewed text. It skips the statistics block, `Source:` and `Sources:` citation lines (a sentence that merely begins with the word "Source" counts) and headings. A sentence does not end at `max.`, `min.`, `ft.`, `lb.`, `lbs.`, `etc.`, `e.g.`, `i.e.`, `rd.`, `cf.` or `vs.`, nor inside an open parenthesis or bracket. A gist that was cut ends in `…` and is never cut inside an open parenthesis; one that fits drops its final period. The abbreviation list is short on purpose: a rare unlisted one only shortens a gist.
- **Rulebooks lead, by tier.** Each level group splits into tiers by `Tier::from_category` of the spell's canonical book, in `Tier::ALL` order, with the title order kept inside a tier. Tier headings appear once a list spans more than one tier. Nothing is hidden: a tier filter would have made "Rulebooks only" the default or an extra control, and the order already puts the common spells first.
- **The school filter is a disclosure of filter pills** (`.chip` checkboxes, the only pill role) inside a native `<details>`, so the chips do not push the rows below the first screen on a phone. The counts are those of the page: on a level page they count that level's spells, and a school with none there is not offered. A school that is still chosen stays listed with its count so it can be cleared. The choice lives in a signal for the page, like the name filter.
- **The row is one link with an overlay.** The link wraps the name, so its accessible name stays the title, and `::after` stretches it over the whole row. Keyboard focus rings the row (`:has(:focus-visible)`).
- **The fact line has two layouts, and the three-line phone row is the owner's choice ("Wide").** From 40 rem it is one line in the owner's order, and the gist gives way first. Below that, casting time, save and book do not fit beside a sentence at 390 px (the gist and the book shrank to a few letters in the first build), so the gist takes its own line under the facts and a phone row is three lines. The owner keeps this as the "Wide" density and wants a reader toggle between Compact (two lines) and Wide later (issue #182, not built here). The list container carries `data-density="wide"`, the only value for now, and the phone-layout CSS is keyed to it, so #182 adds a second value and the control.
- **The class page is a `.jump` on the list page.** The hub picker has one target per class, so the link to the class entry sits on the list page, as a navigation rectangle named `{class} class page`, wherever `list.class` exists.
- **#174 overlap.** The `.spell-class` card, its 3 px top border and its CSS are deleted with the cards, so item 2 of #174 is already done by this change.
