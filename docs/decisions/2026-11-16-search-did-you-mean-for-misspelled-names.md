# Search: "Did you mean" for misspelled names, 2026-11-16

Refs [#166](https://github.com/phynics/cast-iron/issues/166). `magic missle` found nothing, although `firebal` worked, because prefix matching cannot cross a wrong letter. `SearchIndex::suggest_correction` in `crates/search/src/correct.rs` now offers the nearest name. Query time only: `INDEX_FORMAT_VERSION` stays 2 and the compiler is unchanged.

- **Dictionary.** The words of document titles and aliases, built from the stored metadata the first time a correction is asked for and kept in a field that is neither serialized nor part of `SearchIndex` equality. On the canonical library (39,593 documents) that is 15,240 terms and takes about 60 ms once. Body words are not candidates: a title word is what a reader means to look up. Rejected: a stored name-term section (a format bump for something derivable) and the postings dictionary (it holds every body word, and a typo of a rare body word would win).
- **Strong results, defined.** A result is strong when its title or an alias holds every query word, the last as a prefix. A query is *weak* when it has at most `CORRECTION_MAX_HITS` (3) results among the allowed documents and none is strong. Only a weak query is corrected, so `fireball`, `fire` and `firebal` (a prefix of a name) never are. A body-only hit does not make a query strong: a book that prints `missle` in running text must not hide the correction. Callers that already have a result count skip the call above 3, so a broad query pays nothing extra.
- **What may change.** A word is replaced only when it is four or more letters and holds a letter (a number in any script is never rewritten), and is not already a name (or, for the last word, the start of one) that an allowed document carries. The prefix check reads the whole range of names that start with the word and stops at the first allowed carrier; an early cap would call a correct but rare prefix a typo. Edit distance is optimal string alignment: insert, delete, substitute, and a swap of neighbours counts as one. One edit for words under eight letters, two from eight. The last word may also match the start of a name within one edit, so `magic missl` is still corrected while it is being typed. At most three words change, and at most six words are read. A typo that is itself another name (`lite` for `light`) is not corrected: the word is known, and changing known words would rewrite correct queries.
- **A suggestion is verified.** The candidates (three per word, ranked by edits, whole word before prefix, then the name more documents carry, then the text) are combined cheapest first, at most six combinations, and the first whose search has a strong result is offered. A suggestion therefore always finds something under the same books and filters, and the verification is what makes the rest of this list safe.
- **Active books and scope.** The caller passes the same document test it passes to a search (`Discovery::suggest_correction`: entries in active books; book sections in active books on the results page, none in Quick search). Names that only a turned-off book carries are neither candidates nor "known", so they are never suggested. The kind, book and facet filters apply too, and the link keeps them.
- **Deterministic.** The dictionary is sorted text; every ordering ends on the term text. A test builds the same documents in two orders and expects the same answer.
- **Suggest, do not substitute (decision).** The results page shows `Did you mean magic missile?` with the link inside the "No entries match" box, or above the results when a weak query still finds a few. It does not also list the corrected results under a note. The counts, chip numbers and highlights all describe the query that was typed, so a second result set would need its own counts or contradict them, and it doubles the work; one tap on the link is enough. Quick search shows the same words as one row between the suggestions and "See all results", and tapping it opens the corrected results page, as "See all" does. It is not counted as an entry suggestion.
- **Form.** On the results page the link is a `.count-action` (DESIGN.md: accent text, underlined, for an action in an empty state), with no border, pill or fill (Filter is the only pill); the sentence around it is ordinary text. Its hit area is the role's 44 px `::after`, and a test asserts it. In the Quick search row the corrected words are accent and underlined at normal weight, because the row is not a `.count-action`. When a correction is shown in the empty box, the advice line drops "Check the spelling" and reads `Use fewer words, or clear a filter.` No JavaScript and no `inner_html`; the link is a typed `<a href>` to the same search route with only the text replaced.
- **When it runs.** Results page: after the search, only when the page has at most 3 results (entries and sections together). Quick search: inside the existing 100 ms debounce, only when the lookup has at most 3 hits. Per-keystroke use is therefore not needed. Release build, native, on the canonical library, with the host loaded (load average 16): a corrected typo takes 2.4 to 6.8 ms (median of 15; `magic missle` 6.5 ms, `grappel` 5.6 ms, `wizzard` 6.8 ms), a query with no near name 1.6 to 4.1 ms, and a strong query that asks anyway (`fire`, unguarded) 4.6 ms. The browser's WebAssembly time and the table's memory (about 15,000 terms and their document lists, an estimate of 1 to 2 MB beside a 70 MB index) were not measured. The 60 ms table build is not left to the first typo: `Library::search_index` starts a task that builds it 1.5 s after the index loads (`warm_corrections`, a timer in its own task, no new JavaScript), and a correction asked for sooner builds it itself.
- **Limits.** Only the six cheapest combinations of candidates are searched (3 words × 3 candidates is 27), so a correct but distant combination can be missed; the cost stays bounded. Two words typed as one (`fire ball`) or one as two are not joined or split. Transliteration and plural forms are left to the existing prefix match. The correction text is the normalized query (lowercase, no punctuation).
